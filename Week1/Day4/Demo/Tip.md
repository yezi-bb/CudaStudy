# CUDA 硬件核心概念：SM、Warp、Block 完整分层讲解

## 一、从宏观硬件到最小调度单元层级关系

GPU 芯片 → 多个 **SM（流多处理器）**

每个 SM → 同时承载若干个 **Block（线程块）**

每个 Block → 自动切分成若干个 **Warp（32 线程调度组）**

Warp → 32 个独立 Thread（线程）

层级从大到小：

```
GPU芯片 > SM > Block > Warp > Thread
```

## 二、SM —— GPU 真正的计算核心（硬件实体）

### 1. 什么是 SM

SM = Streaming Multiprocessor，流多处理器，是 GPU 上独立、完整的计算单元，是真正执行代码的硬件。

你的 4060 Ada 架构有大量 SM，每个 SM 独立拥有一套资源：

- 运算单元（FP32 浮点、INT 整数、ALU）
- 共享内存 `__shared__`
- 寄存器堆（每个线程私有的寄存器）
- L0 指令缓存、L1 数据缓存
- Warp 调度器、分发单元

### 2. SM 工作逻辑

1. CPU 提交 Grid（一堆 Block）给 GPU；
2. GPU 调度器把空闲的 Block 分配给任意空闲 SM；
3. 一个 Block**只能完整驻留在同一个 SM 中**，Block 不能跨 SM 拆分；
4. 一个 SM 同一时刻可以同时容纳多个 Block，取决于资源（寄存器、共享内存）够不够。

### 3. 关键限制

如果你的 Block 设为 1024 线程，单个 Block 占用大量寄存器 / 共享内存，一块 SM 可能只能放下 1 个 Block；

如果 Block=256，资源占用小，一块 SM 可以同时放下 4~8 个 Block，并发更高，速度更快。

## 三、Block（线程块）—— 软件分组逻辑，硬件依附 SM

### 1. Block 实质是什么？

Block 是**软件层面的线程分组**，是程序员能直接控制的单位，由你在 `<<<grid, block>>>` 指定。

作用：

1. 同一 Block 内所有线程可以共享 `__shared__` 共享内存、同步 `__syncthreads()`；
2. Block 是 GPU 分配到 SM 的最小单位；
3. Block 之间完全隔离，无法互相访问共享内存、无法同步。

### 2. Block 硬性规则

1. 单个 Block 线程上限：**1024**（硬件强制）；
2. 一个 Block 所有线程必须全部放在同一个 SM，不能拆分；
3. Block 之间无通信、无同步；
4. Grid 里所有 Block 逻辑上并行，硬件上由 SM 分批调度执行。

### 3. Block 大小带来的性能差异

- Block=1024：单块资源吃满，单个 SM 容纳 Block 数量极少，并发低；
- Block=256/128：资源适中，单 SM 可同时放多个 Block，大量 Warp 切换隐藏显存延迟，性能最优；
- Block 过小（32/64）：单块 Warp 太少，线程切换不足，延迟掩盖能力弱。

## 四、Warp —— SM 最小硬件调度单位（重中之重）

### 1. Warp 实质

一个 Warp 固定包含 **32 个 Thread**，是 SM 调度、执行指令的最小粒度，由硬件自动切分，程序员无法修改。

无论你 Block 设为 256、1024，硬件都会自动按每 32 个线程打包成 Warp。

示例：

- Block=256 线程 → 256 / 32 = 8 个完整 Warp
- Block=100 线程 → 4 个完整 Warp (128 线程)，最后一个 Warp 只用到 4 个线程，剩余 28 个硬件空跑（资源浪费）

### 2. SIMT 单指令多线程执行模式

SM 对同一个 Warp 内 32 个线程**同时执行同一条指令**：

1. 如果 Warp 内所有线程执行完全相同代码（无分支 if/else）：32 线程并行满速运行，硬件利用率 100%；

2. 如果 Warp 内线程出现分支（一部分走 if，一部分走 else）：

   分支分化（Warp Divergence）

   SM 只能分批执行：先执行 if 分支的线程，再阻塞等待、执行 else 分支，性能直接腰斩。

示例分支分化：

cpp

运行

```
if(threadIdx.x % 2 == 0)
    d_out[idx] = d_a[idx] + 1;
else
    d_out[idx] = d_a[idx] - 1;
```

同一个 Warp 里奇偶线程走不同分支，产生严重性能损耗。

### 3. Warp 延迟隐藏（GPU 高性能的核心原理）

访问全局显存速度极慢，一次读取需要几百个时钟周期；

CPU 遇到等待会阻塞，而 SM 有大量 Warp 可以切换：

1. 当前 Warp 去读显存，进入等待状态；
2. SM 立刻切换另一个就绪的 Warp 执行运算；
3. 不断轮换 Warp，硬件计算单元始终不空闲；

想要充分隐藏延迟，必须保证 SM 内有足够多活跃 Warp，这就是为什么不推荐超大 Block (1024)。

## 五、三者联动完整执行流程（举例）

配置：`<<<40, 256>>>`

1. Grid 一共 40 个 Block，每个 Block256 线程；
2. 每个 Block 自动拆分为 256/32=8 个 Warp；
3. GPU 把 Block 分发到空闲 SM；
4. 每个 SM 同时持有多个 Block，内部存在大量活跃 Warp；
5. 某个 Warp 读取显存阻塞，硬件立刻调度其他 Warp 运算；
6. 同一 Block 内线程可用共享内存交换数据、`__syncthreads()` 块内同步；
7. Block 之间完全独立，无法同步、无法访问对方共享内存。

## 六、核心总结

1. **SM**：物理硬件计算单元，所有线程代码最终在 SM 上运行，自带寄存器、共享内存；
2. **Block**：软件分组，程序员可控，块内可共享内存、同步；一个 Block 不能跨 SM；单块最大 1024 线程；
3. **Warp**：硬件调度最小单元，固定 32 线程；Warp 分化会大幅降速；依靠多 Warp 切换隐藏显存延迟；
4. 最优工程配置：Block=256，32 的整数倍，Warp 无浪费，SM 可容纳多 Block，并发充足，性能均衡。
