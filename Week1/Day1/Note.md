# CUDA 架构核心概述（Host/Device、内存、版本匹配）

## 一、Host（CPU）与 Device（GPU）核心区别

CUDA 采用**异构计算架构**，明确拆分主机端（CPU）与设备端（GPU），二者职责、硬件、执行模型完全隔离。

### 1. 基础定义

- **Host（主机）**：传统 CPU，运行**操作系统、应用主线程、业务逻辑**，串行处理复杂分支、逻辑判断、系统交互。
- **Device（设备）**：NVIDIA GPU，专为**大规模并行计算**设计，负责密集型数值运算、矩阵运算、流式任务。

### 2. 核心差异对比

表格

|   维度   |                     Host (CPU)                     |                         Device (GPU)                         |
| :------: | :------------------------------------------------: | :----------------------------------------------------------: |
| 架构设计 | 少量大核，**复杂指令集**，侧重串行、逻辑、缓存优化 |   大量小计算核心（CUDA Core），**精简指令**，侧重并行吞吐    |
| 执行模型 |   单 / 多线程串行执行，分支、跳转、函数调用友好    | 线程分组并行（Thread/Block/Grid），**忌复杂分支**，分支会大幅降速 |
| 运算特点 |          延迟优先，擅长复杂逻辑、随机访问          |        吞吐优先，擅长**规整、批量、无分支**的重复计算        |
| 代码运行 |     普通 C/C++ 代码、系统 API、文件 / 网络 IO      |      CUDA Kernel 核函数（`__global__`），仅在 GPU 执行       |
| 调度逻辑 |              操作系统进程 / 线程调度               |         GPU 硬件硬件调度线程束（Warp，默认 32 线程）         |
| 数据交互 |            主动发起数据拷贝、调用核函数            |              被动执行计算，无法主动访问主机资源              |

### 3. 典型协作流程

1. Host 初始化数据、分配**主机内存**；
2. Host 调用 `cudaMemcpy` 将数据拷贝至 GPU 显存；
3. Host 启动 **CUDA Kernel**，GPU 并行执行计算；
4. GPU 计算完成后，数据拷贝回主机内存；
5. Host 做结果后处理、逻辑判断、输出。

> 关键约束：**GPU 不能直接执行主机代码，CPU 不能直接调用 GPU 内部硬件单元**，二者通过 CUDA Runtime 做交互。

## 二、主机内存（内存）与设备显存（显存）差异

CUDA 中**内存（Host Memory）** 和**显存（Device Memory）** 是两块独立物理空间，不能直接互访，必须显式拷贝。

### 1. 基础概念

- **主机内存（Host Memory）**：CPU 可直接读写的系统内存（DRAM），由操作系统管理。
- **设备显存（Device Memory / Global Memory）**：GPU 板载专用显存（GDDR6/GDDR6X/HBM 等），仅 GPU 计算核心直接访问。

### 2. 核心差异

1. **物理隔离**

   两块独立硬件，**地址空间完全分离**，CPU 无法直接读取显存，GPU 无法直接读取普通主机内存，必须通过 `cudaMemcpy` 显式传输。

2. **带宽 & 延迟**

   - 显存：**带宽极高**（数百 GB/s ~ TB/s 级别），适合批量数据吞吐；访存延迟偏高，依赖**连续访存、合并访存**优化。
   - 主机内存：带宽远低于显存，但随机访存、小数据访问延迟更低。

3. **内存分类（CUDA 专属）**

   #### （1）主机内存分类

   - **普通页内存（Pageable Host Memory）**：系统默认内存，可被操作系统换页到磁盘，**拷贝速度慢**，通用场景使用。
   - **锁页内存（Page-Locked / Pinned Memory）**：内存被锁定在物理内存、不换页，**CPU<->GPU 拷贝速度大幅提升**；缺点：占用物理内存，过多会导致系统卡顿。

   #### （2）GPU 显存分层（从快到慢）

   - **寄存器（Register）**：每个线程私有，速度最快，容量极小；
   - **共享内存（Shared Memory）**：线程块（Block）内线程共享，片上高速存储，常用作数据缓存 / 中转；
   - **全局显存（Global Memory）**：GPU 主存，容量最大、速度最慢，全局所有线程可见；
   - 常量内存、纹理内存：特殊优化显存，用于只读数据、图像采样等场景。

4. **数据传输方向**

   仅三种合法拷贝：

   - 主机内存 → 显存（计算前传输入数据）
   - 显存 → 主机内存（计算后取回结果）
   - 显存 → 显存（GPU 内部数据迁移，无需 CPU 参与）

## 三、CUDA Toolkit 版本匹配规则

CUDA 版本必须和 **GPU 算力（架构）、显卡驱动、操作系统、编译器** 严格匹配，否则编译 / 运行报错。

### 1. 核心前置概念

- **GPU 算力（Compute Capability，CC）**：标识 GPU 硬件架构（如 7.5=Turing、8.0=Ampere、8.6=RTX30、9.0=Hopper、10.x=Blackwell），**硬件固定，无法修改**。
- **CUDA Toolkit**：开发套件（编译器 `nvcc`、Runtime、库、头文件），用于代码编译、开发。
- **NVIDIA 显卡驱动（Driver）**：系统层面驱动，负责 GPU 硬件调度、CUDA 运行时支持。

### 2. 三大核心匹配规则（优先级从高到低）

#### 规则 1：驱动版本 ↔ CUDA Toolkit 版本（运行时兼容）

NVIDIA 驱动**向下兼容 CUDA**，**向上不兼容**：

> **新驱动可以运行旧 CUDA；旧驱动不能运行新 CUDA**

官方约束：每个 CUDA 版本有**最低驱动版本要求**，驱动版本必须 ≥ CUDA 要求的最低驱动。

示例（常用版本最低驱动，Windows/Linux 略有差异，取通用参考）：

- CUDA 11.2 → 最低驱动 460.27
- CUDA 11.8 → 最低驱动 520.61
- CUDA 12.1 → 最低驱动 530.39
- CUDA 12.4 → 最低驱动 550.54

查询命令：

bash运行

```
# 查看当前驱动版本、支持的最高 CUDA
nvidia-smi
```

`nvidia-smi` 右上角会显示 **Driver Version** 和 **CUDA Version**（代表当前驱动**最高兼容的 CUDA 版本**）。

> 实操原则：安装的 CUDA Toolkit 版本 **≤ nvidia-smi 显示的 CUDA 版本**。

#### 规则 2：CUDA Toolkit ↔ GPU 算力（编译兼容）

CUDA 编译器 `nvcc` 需要指定**目标算力**（`-arch=sm_XX`），规则：

1. **高版本 CUDA 支持所有老旧算力**；
2. **低版本 CUDA 不支持新硬件算力**；
3. 编译时必须指定当前 GPU 对应的算力，否则报错 / 无法使用硬件特性。

举例：

- RTX30 系列（CC 8.6）：最低支持 CUDA 11.0+
- RTX40 系列（CC 8.9）：最低支持 CUDA 11.8+
- A100（CC 8.0）：CUDA 11.x/ 12.x 全支持

编译参数示例：

bash

运行

```
# 针对 8.6 算力（RTX30）编译
nvcc -arch=sm_86 test.cu -o test
```

#### 规则 3：CUDA Toolkit ↔ 系统 & 编译器

1. **操作系统**

   - Windows：区分 Win10 / Win11、Server 版本，新 CUDA 不再支持老旧系统；
   - Linux：严格匹配发行版（Ubuntu/CentOS/RHEL）、内核版本。

2. **主机编译器（GCC / MSVC）**

   `nvcc` 对 CPU 编译器版本有**严格上限限制**：

   - Linux 下：CUDA 11.x 通常最高支持 GCC 9/10；CUDA 12.x 逐步支持更高 GCC；**高版本 GCC 无法编译低版本 CUDA**。
   - Windows 下：CUDA 对应指定 Visual Studio 版本（MSVC 编译器），比如 CUDA12.1 推荐 VS2019/VS2022。

### 3. 工程落地最佳实践

1. 先执行 `nvidia-smi`，确认**驱动最高兼容 CUDA 版本**；
2. 选择 **小于等于该版本** 的 CUDA Toolkit；
3. 确认本机 GCC/VS 编译器版本在 CUDA 允许范围内；
4. 根据自己 GPU 算力，编译时添加对应 `-arch=sm_XX` 参数；
5. 多版本 CUDA 共存：通过环境变量 `PATH`、`LD_LIBRARY_PATH` 切换默认版本。

### 4. 常见避坑点

- 误区 1：`nvidia-smi` 显示的 CUDA ≠ 本机安装的 CUDA Toolkit，前者是**驱动兼容上限**，后者是**开发版本**；
- 误区 2：新 GPU 用老 CUDA：新算力硬件必须使用对应及以上版本 CUDA，否则编译失败；
- 误区 3：只升级 CUDA 不升级驱动：驱动版本不足，运行时直接报 `cudaErrorInvalidDevice`。

------

## 精简总结

1. **Host/Device**：CPU 串行逻辑、GPU 并行计算，异构协作，代码执行空间隔离；
2. **内存 / 显存**：物理独立、不能直接互访，显存带宽更高，主机内存分普通 / 锁页，GPU 显存分层设计；
3. **版本匹配**：驱动向下兼容 CUDA、CUDA 向下兼容旧算力、CUDA 绑定系统 / 编译器，优先以 `nvidia-smi` 结果为选型依据。
