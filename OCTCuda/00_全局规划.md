## 1. 最终目标（可验收）

完成计划后，你应同时具备三层能力：

| 层次 | 能力 | 验收物 |
|------|------|--------|
| **理解层** | 能不看稿讲清 `VGPU_Process.cuh` 各 region 的职责、输入输出、与宿主线程关系 | 自写的「API 心智图」+ 口述录音/笔记 |
| **实现层** | 能用 CUDA 复现：重采样/窗 → cuFFT/Log → Transpose → DSC → 增强/伪彩 → 回拉批处理骨架 → IPA μ 估计骨架 | 独立 GitHub 仓 + 单元测试 |
| **工程/求职层** | Streams/Pinned、显存生命周期、Nsight 前后对比、简历数字 | README 性能表 + 简历草稿 |

**「完全理解融合 OCT 中 CUDA 部分」的操作定义：**

1. 对 `VGPU_Process.cuh` **每一个** `extern "C"` 接口能回答：干什么、谁调用、数据在 Host 还是 Device、失败时宿主怎么处理。  
2. 能手绘 Scan 实时链、Pullback 批处理链、Analysis 链、IPA 链四张图。  
3. 对闭源部分能给出**合理的 CUDA 实现假设**（kernel 划分、内存布局、与 cuFFT 的边界），并用开源复现验证自己的假设。  
4. 对 IPA：说清 `att_paras`、μ 矩阵、毯展图、`VGPU_UpdateValueIPA` 与 UI 阈值的关系。

## 2. 仓库现状与学习策略

### 2.1 事实

| 项 | 说明 |
|----|------|
| 内核 | **无**一等公民 `.cu` 业务源码；算法在 `VGPU_Process.dll` |
| API | `Algorithm/vgpu/include/VGPU_Process.cuh`（约 70+ 导出） |
| 宿主 | `ImageProcessingController` / `GpuHandlingDataThreadController` / `IPAAlgorithmController` 等 |
| 工具链 | CUDA 12.4 头文件、`cudart` + `cuFFT` 链接；无 app 侧 nvcc 编译步骤 |
| IPA | 现并入 `VGPU_*`；`08Code/.../IpaAlgorithmKernel.cuh` 为旧拆分 API，可对照演进 |

### 2.2 策略（读公司代码 ≠ 抄公司代码）

```text
读 API 签名与注释
    → 读宿主调用上下文（参数从哪来、结果去哪）
    → 推断 device buffer 生命周期与 is_device_to_host 策略
    → 查阅公开 OCT / 光衰减文献，形成可公开的算法规格
    → 在独立仓实现 CPU 黄金版 → CUDA naive → 优化
    → 用合成数据 + 数值误差 + Nsight 证明理解正确
```

## 7. 合规与伦理

- 不逆向、不反汇编 `VGPU_Process.dll` 作为公开材料。  
- 不上传医院数据、原始 pullback、内部 `IPAParmenter` 真值表到公开仓。  
- 公开算法描述使用通用术语：spectral OCT reconstruction、scan conversion、attenuation coefficient estimation。  
- 公司代码路径仅写在**本 OCTCuda 私有学习笔记**中；开源 README 不写内部函数名亦可（推荐写「等价功能模块名」）。
